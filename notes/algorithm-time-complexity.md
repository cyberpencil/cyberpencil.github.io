# 常见算法时间复杂度符号（从小到大排序）

> 复杂度描述的是**输入规模 n 增大时，运行时间（或空间）的增长趋势**，不是精确的秒数。  
> 记住一个核心结论：**常数和低阶项在 n 足够大时可以忽略**，比如 `3n² + 500n + 9999` 记作 `O(n²)`。

## 一、从小到大排序（速查）

```tex
O(1)  <  O(log log n)  <  O(log n)  <  O(√n)  <  O(n)
      <  O(n log n)  <  O(n²)  <  O(n³)  <  O(2ⁿ)  <  O(n!)  <  O(nⁿ)
```

|  序号 | 符号           | 名称    | 增长率直觉     | 典型算法 / 场景                           |
| :-: | ------------ | ----- | --------- | ----------------------------------- |
|  1  | O(1)         | 常数阶   | 与 n 完全无关  | 数组下标访问、哈希表查找（均摊）、入栈/出栈、头插法          |
|  2  | O(log log n) | 双重对数阶 | 几乎等于常数    | van Emde Boas 树、插值查找、两次二分（少见但要认识）   |
|  3  | O(log n)     | 对数阶   | 每次问题规模减半  | 二分查找、平衡二叉树查找、求幂、堆的单次调整              |
|  4  | O(√n)        | 平方根阶  | 分块处理      | 分块查找、块状数组、试除法判素数、枚举约数               |
|  5  | O(n)         | 线性阶   | 一趟扫描      | 线性查找、遍历数组/链表/树、计数排序、双指针、单调栈         |
|  6  | O(n log n)   | 线性对数阶 | 分治 + 线性合并 | 归并排序、快速排序（平均）、堆排序、排序后二分、CDQ 分治      |
|  7  | O(n²)        | 平方阶   | 双重循环      | 冒泡/选择/插入排序、Floyd 最短路、朴素 LCS、朴素字符串匹配 |
|  8  | O(n³)        | 立方阶   | 三重循环      | 朴素矩阵乘法、区间 DP、Floyd（按点集实现）           |
|  9  | O(2ⁿ)        | 指数阶   | 每层规模翻倍    | 朴素递归斐波那契、子集枚举、暴力搜索/回溯、状态压缩 DP       |
|  10 | O(n!)        | 阶乘阶   | 全排列级爆炸    | 旅行商问题暴力解、全排列、无剪枝回溯                  |
|  11 | O(nⁿ)        | 幂塔阶   | 理论上更慢     | 枚举所有「长度为 n 的 n 元组」的暴力解              |

## 二、增长量对照表

下表的数字是**基本操作次数**的量级（不是秒）。工程经验：1 秒大约能完成 10⁸ 次简单操作。

| 复杂度        |     n = 10 |      n = 100 |      n = 1000 | n = 10⁶ |
| ---------- | ---------: | -----------: | ------------: | ------: |
| O(1)       |          1 |            1 |             1 |       1 |
| O(log n)   |          3 |            7 |            10 |      20 |
| O(√n)      |          3 |           10 |            32 |    1000 |
| O(n)       |         10 |          100 |          1000 |     10⁶ |
| O(n log n) |         33 |          664 |         9 966 | 2 × 10⁷ |
| O(n²)      |        100 |          10⁴ |           10⁶ |    10¹² |
| O(n³)      |        10³ |          10⁶ |           10⁹ |    10¹⁸ |
| O(2ⁿ)      |       1024 | ≈1.27 × 10³⁰ | ≈1.07 × 10³⁰¹ |    天文数字 |
| O(n!)      | ≈3.6 × 10⁶ | ≈9.3 × 10¹⁵⁷ | ≈4.0 × 10²⁵⁶⁷ |    天文数字 |

> 换成人话：`O(n log n)` 在 n = 10⁶ 时一秒钟能跑完；`O(n²)` 同样的规模要跑 **10⁴ 秒 ≈ 3 小时**；`O(2ⁿ)` 在 n = 100 时宇宙寿命也跑不完。

## 三、读法上的三个关键点

### 1. O、Ω、Θ 不是一回事

| 记号      | 含义                | 类比      |
| ------- | ----------------- | ------- |
| O(f(n)) | **上界**，增长不快于 f(n) | "最多这么大" |
| Ω(f(n)) | **下界**，增长不慢于 f(n) | "至少这么大" |
| Θ(f(n)) | **紧确界**，上下界同阶     | "就是这么大" |

日常说「这个算法是 O(n log n)」其实想表达的是 Θ(n log n)，只是习惯用大写 O。严格写论文时要分清。

### 2. 同一算法有最好 / 最坏 / 平均 / 均摊

- **快速排序**：最好 `O(n log n)`、平均 `O(n log n)`、最坏 `O(n²)`（已有序且取端点为基准时）。
- **哈希表查找**：平均 `O(1)`，最坏 `O(n)`（全部冲突到同一个桶）。
- **动态数组 append**：单次最坏 `O(n)`（扩容复制），但**均摊** `O(1)`。

面试或写文档时，**不指明是最坏情况就默认说最坏或平均**，两者不一致时必须说明。

### 3. 常见的几个认知误区

- `O(1)` 不等于「快」。一次 `O(1)` 操作如果内部是 10⁶ 次循环，仍然可能比某个 `O(n)`（n = 100）慢。O 只描述**趋势**。
- 忽略常数有前提。n 很小的时候，`O(n²)` 的插入排序往往比 `O(n log n)` 的归并排序更快——这也是 `std::sort` 在小数组上退化成插入排序的原因。
- 空间复杂度用同一套符号。归并排序 `O(n)`、快排 `O(log n)`（递归栈）、原地排序 `O(1)`。
- 循环层数 ≠ 复杂度。`for i in range(n): i *= 2` 是 `O(log n)`；两层循环若内层按倍数收缩，也可能是 `O(n log n)`。

## 四、工程上的分量级判断

| 输入规模 n      | 可接受的复杂度上限              |
| ----------- | ---------------------- |
| n ≤ 12      | O(n!)（12! ≈ 4.8 × 10⁸） |
| n ≤ 25      | O(2ⁿ)（2²⁵ ≈ 3.3 × 10⁷） |
| n ≤ 500     | O(n³)                  |
| n ≤ 5 000   | O(n²)                  |
| n ≤ 2 × 10⁵ | O(n log n)             |
| n ≤ 10⁸     | O(n)                   |
| 任意          | O(log n)、O(1)          |

这张表可以直接反推解法：看到 `n ≤ 25` 就想状态压缩或暴力搜索；看到 `n = 10⁵` 就必须往 `O(n log n)` 或更低去设计；看到 `n = 10⁹` 只剩 `O(log n)` 或 `O(1)` 的数学解法。

## 五、一行总结

**从快到慢：常数 → 双重对数 → 对数 → 平方根 → 线性 → 线性对数 → 平方 → 立方 → 指数 → 阶乘。**

设计算法的主线，就是想办法把复杂度往左推一格：`O(n²)` → `O(n log n)` 靠排序与分治，`O(n²)` → `O(n)` 靠哈希与双指针，`O(2ⁿ)` → `O(n²)` 靠记忆化与 DP。
